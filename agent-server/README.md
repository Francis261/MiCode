# MiCode Agent Server

A separate Node.js API for the Expo MiCode client. It provides an OpenAI-compatible coding-agent loop with server-sent events, temporary GitHub repository workspaces, Docker-isolated project commands, GitHub pull-request and Actions APIs, and static preview serving.

## Setup

Requires Node.js 20+ and Docker.

```bash
cd /root/MiCode/agent-server
npm run setup
```

This creates a private `.env` file with a random `MICODE_SERVER_TOKEN`. Read that value locally and enter it in MiCode Settings → MiCode agent server. Never commit `.env`.

Configure these values in `.env`:

- `PORT=8788`
- `MICODE_SERVER_TOKEN`: generated by setup.
- `AI_BASE_URL`: OpenAI-compatible API base URL.
- `AI_API_KEY`: provider key, stored only on this server.
- `AI_MODEL`: model name supported by the configured provider.
- `MICODE_PUBLIC_URL`: public HTTPS origin if the server is exposed through a reverse proxy/tunnel.

Start:

```bash
npm run start:detached
```

Health: `GET /health`; authenticated capability status: `GET /v1/status`.

## Renewable GitHub Actions runtime (initial integration)

The server now exposes `POST /v1/github/install-runtime`. It installs the renewable runtime into a repository using the supplied GitHub token:

- `.github/workflows/micode-agent.yml`
- `MiCode/runtime/agent-server.js`
- `MiCode/runtime/runner.js`
- `MiCode/runtime/prepare.js`
- `MiCode/runtime/README.md`

The workflow defaults to a 270-minute (4h 30m) handoff interval. The runner creates a dedicated `micode/agent/<session-id>` branch, creates continuation/checkpoint files, starts the coding API, and exposes it using a Cloudflare Quick Tunnel. At handoff it commits and pushes the checkpoint branch; it never force-pushes or writes to the user's default branch.

Before dispatching the workflow, repository Actions secrets must be configured for the control-plane callback URL/token, agent token, and AI provider credentials. The token used to install a workflow file needs repository Contents: write and Workflows: write permissions. The workflow's built-in token needs Contents: write to push its checkpoint branch.

The runner template is a first implementation milestone, not yet a complete unattended renewal service: the persistent callback/event registry, notification/approval UI, automatic next-run dispatch, secure per-project credential storage, and end-to-end reconnection still need implementation. Do not expose this as production-ready until those pieces are completed and tested.

## Features

- `POST /v1/sessions`: clones a GitHub repository into a temporary workspace. The GitHub token is used for the clone and is not persisted in session metadata.
- `POST /v1/agent/stream`: streams provider tokens to the app using SSE. The model can list/read/write repository files and run a small allowlist of checks.
- `POST /v1/sessions/publish`: commits the agent's workspace changes and pushes a new branch to GitHub.
- `POST /v1/terminal`: executes an explicit allowlist inside a Docker container with memory/CPU/PID limits, no Linux capabilities, no-new-privileges, read-only container root and no network access.
- `POST /v1/preview/build`: installs dependencies in an isolated build container, builds the app, and starts a read-only static preview container for recognized output folders. The server proxies `/preview/<session-id>/...` to that container.
- `GET/POST /v1/github/pulls`: list open pull requests and create a pull request from a pushed branch.
- `GET /v1/github/actions/workflows`, `GET /v1/github/actions/runs`, `POST /v1/github/actions/dispatch`: discover workflows, inspect runs, and dispatch a workflow.

## GitHub fine-grained token permissions

Select only the repositories MiCode should access and grant:
- Metadata: read-only.
- Contents: read and write (clone/read/write repository content and push a branch).
- Pull requests: read and write.
- Actions: read and write.
- Repository creation: write only if the user wants MiCode to create repositories.

The GitHub token is stored by Expo SecureStore on native devices and sent to the backend for the specific GitHub operation. Do not use this PAT on an untrusted device.

## Important deployment/security limitations

This is an initial single-workspace backend, not a production multi-tenant SaaS service yet. It currently uses one shared server bearer token, keeps sessions in process memory, and stores cloned repositories in a local workspaces directory. Restarting the server loses session mappings. Before production use, add user authentication, per-user authorization and quotas, durable session metadata, workspace cleanup, audit logs, per-user secret storage, request size/time limits, egress controls, container hardening, and an authenticated preview gateway. Keep the backend behind HTTPS and restrict access. The preview URL is a bearer-like capability URL and should not be shared publicly.

The agent requires a valid `AI_API_KEY`; without it, the API reports that the provider is not configured. The app can still use GitHub pull-request and Actions APIs once the backend and GitHub token are configured. A live preview requires `MICODE_PUBLIC_URL` to be a reachable HTTPS origin that forwards to this server.
